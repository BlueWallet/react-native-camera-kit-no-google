# CameraKit macOS example

Independent AppKit application using React Native macOS **0.83.0**, React Native
**0.83.10**, React **19.2.0**, macOS **14+**, Fabric and TurboModules. It uses the
parent library through `react-native-camera-kit-no-google: file:..`.

The Xcode project comes from the Microsoft 0.83.0 template (with the Swift
initializer corrected to initialize stored properties before `super.init()`).
See the [Microsoft setup guide](https://microsoft.github.io/react-native-macos/docs/getting-started).

## Install and run

Use Xcode with its command-line tools, Node >=20.19.4 and CocoaPods. From this folder:

```sh
npm ci
npm run pods
npm start
```

In another terminal, in this folder:

```sh
npm run macos
```

Build without launching: `npm run build`. Release: `npm run build -- --mode Release`.
Type check: `npm run typecheck`. The checked-in npm and CocoaPods lockfiles pin
this example independently of the mobile example. `Podfile` enables the new
architecture explicitly. Metro maps React Native imports to `react-native-macos`
and resolves dependencies from this app, including imports inside the linked library.

Click **Запросить разрешение** to request access. If access was denied, enable
CameraKitMacOS under System Settings → Privacy & Security → Camera and return to
the app. It rechecks authorization when active. **Системная** uses the AVFoundation
system default; a disconnected explicit selection stays selected until you change it.

The camera entitlement and usage description are already included. Continuity
Camera discovery is enabled in Info.plist; availability depends on your hardware
and macOS settings.

## Verification

From the repository root, `npm run test:macos` runs native device-selection,
event-throttling, stale-result and Vision image-decoding tests without requesting
camera access. Known QR images are generated by Core Image, including different
payloads and all eight image orientations. `npm test -- --runInBand` also tests
platform module selection and unsupported mobile device enumeration.

Hardware acceptance checks (run on an actual Mac):

- On a fresh app identity, request access; verify both allow and deny paths and
  relaunch after changing permission in System Settings.
- Select built-in and USB cameras, disconnect/reconnect the selected camera, and
  verify it never silently falls back. Try Continuity Camera if available.
- Present a static QR and then distinct QR frames every 500 ms. With a 100 ms
  throttle, the event count must keep increasing even for repeated payloads.
  This example displays frames; it does not assemble UR/fountain-code sequences.
- Turn scanning off: the preview stays visible and events stop. Close the camera:
  events stop and the camera indicator turns off. Reopen and scan again.
- Resize the window and switch `cover`/`contain`; verify crop versus letterboxing.
- Close the window during scanning; confirm the capture session releases the camera.

Validated during implementation on 2026-10-11: macOS Debug build and `run-macos`,
Fabric/TurboModule registration, granted permission across app relaunch, built-in
FaceTime and Dell USB previews, switching cameras, a live static QR with repeated
events, both preview modes, window resize and camera close/reopen. The sandboxed
app signature includes the camera entitlement. TypeScript, JS tests, 65 Swift and 3 Objective-C++ native
assertions, Metro bundling, iOS Simulator and Android arm64 Debug builds passed.

Still requiring manual acceptance: denied permission followed by changing it in
System Settings, unplug/replug during capture, Continuity Camera, and a live
animated sequence changing every 500 ms. Automated image tests cover distinct QR
payloads, but do not prove capture timing with a physical display.

RN 0.83 development builds warn about the library's existing deep import of
`codegenNativeComponent`; it is retained for compatibility with the mobile RN
versions. Repository ESLint currently cannot start because `eslint-plugin-import`
is missing from its development install.
