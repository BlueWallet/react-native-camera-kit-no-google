# CameraKit example

One application for iOS, Android and macOS, with a shared entry point, QR scanner,
package.json and Yarn lockfile. It uses React Native **0.83.10**, React Native macOS
**0.83.0**, React **19.2.0**, Fabric and TurboModules. The local library is linked
under its published name, `react-native-camera-kit-no-google`.

## Install and run

Use Node >=20.19.4 and Yarn Classic. Apple builds require Xcode and CocoaPods;
macOS requires macOS 14+. Android requires JDK 17 and the Android SDK (API 36).
See the [Microsoft setup guide](https://microsoft.github.io/react-native-macos/docs/getting-started)
for the macOS toolchain. From the repository root:

```sh
yarn install --frozen-lockfile
yarn --cwd example install --frozen-lockfile
# Install pods only for the platforms you intend to build:
yarn --cwd example pods:ios
yarn --cwd example pods:macos
yarn --cwd example start
```

In another terminal, choose a platform:

```sh
yarn --cwd example ios
yarn --cwd example android
yarn --cwd example macos
```

Build macOS without launching: `yarn --cwd example build:macos`.
Type check: `yarn --cwd example typecheck`.
Build Android without launching: `cd example/android && ./gradlew assembleDebug`.
The iOS workspace is `example/ios/CameraKitExample.xcworkspace`.

Metro resolves React and native dependencies from this app's node_modules. It maps
React Native imports to `react-native-macos` only for macOS bundle requests.
`RN_PLATFORM=macos` selects macOS autolinking and disables the mobile image picker;
the macOS scripts and Podfile set it automatically. iOS and Android use the standard
React Native package. Each Apple project has its own CocoaPods lockfile.

## Screens

- **Barcode Scanner** is shared: permission request, preview, 100 ms QR events,
  scanning toggle, camera close/reopen, last payload and event counter.
- macOS adds a device list with **System default**, refresh and disconnected states.
  Mobile offers front/back selection. Preview cover/contain is available on iOS/macOS.
- **Detect QR from Image** uses the mobile photo picker or a base64/data-URI input on macOS.
- **Camera**, **Barcode controls** and **Mount Stress Test** retain the mobile demos.
  Photo capture, face detection and mobile camera controls are not available on macOS.

Click **Request permission** to request access. If access was denied, enable
CameraKitMacOS under System Settings → Privacy & Security → Camera and return to
the app. It rechecks authorization when active. **System default** uses the AVFoundation
system default; a disconnected explicit selection stays selected until you change it.

The camera entitlement and usage description are already included. Continuity
Camera discovery is enabled in Info.plist; availability depends on your hardware
and macOS settings.

## Verification

From the repository root, `npm run test:macos` runs native device-selection,
event-throttling, stale-result and Vision image-decoding tests without requesting
camera access. Known QR images are generated by Core Image, including different
payloads and all eight image orientations. `npm test -- --runInBand` also tests
platform module selection and unsupported mobile device enumeration.

Hardware acceptance checks (run on an actual Mac):

- On a fresh app identity, request access; verify both allow and deny paths and
  relaunch after changing permission in System Settings.
- Select built-in and USB cameras, disconnect/reconnect the selected camera, and
  verify it never silently falls back. Try Continuity Camera if available.
- Present a static QR and then distinct QR frames every 500 ms. With a 100 ms
  throttle, the event count must keep increasing even for repeated payloads.
  This example displays frames; it does not assemble UR/fountain-code sequences.
- Turn scanning off: the preview stays visible and events stop. Close the camera:
  events stop and the camera indicator turns off. Reopen and scan again.
- Resize the window and switch `cover`/`contain`; verify crop versus letterboxing.
- Close the window during scanning; confirm the capture session releases the camera.

The macOS project originated from Microsoft's 0.83.0 template. Its sandbox camera
entitlement, permission description and Continuity Camera discovery flag are included.

Hardware checks involving denied permission recovery, physical unplug/replug,
Continuity Camera and a live animated sequence require manual acceptance.

Validated after unification: root/example TypeScript, JS/native tests, frozen Yarn
install, both CocoaPods projects, production bundles for all three platforms,
Android arm64 Debug, iOS Simulator Debug and macOS Debug builds. `run-macos`
launches the shared menu and QR screen and enumerates built-in/USB cameras.
